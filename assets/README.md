# uwuStack assets for Unity

Everything the web game draws and plays, taken out of the code that made it
at runtime and saved as files a Unity project can use. Built for **Unity 6
with URP** (the default 3D template), in linear colour space.

Copy the folders into your project's `Assets/`, keeping the `.meta` files:
they hold the IDs that wire materials to shaders and textures, and meshes
to materials.

Everything except `Shaders/`, `Scripts/` and this file is generated by
`node scripts/unity-export/export.mjs`; change the game, then run that
again.

## What is where

| Folder | What | Made from |
| --- | --- | --- |
| `Audio/` | Every sound, ready to play: the recordings trimmed to where the game starts them (`Hit`, `Splash`, `Grow`), the seamless water loop, and the synthesised ones rendered to WAV (`Drop1-3`, `Land1-3`, `GameOver`, `Perfect01_C3` to `Perfect22_C6`) | `main-site/sounds/`, `js/audio.js` |
| `Audio/Originals/` | The four recordings, untouched | `main-site/sounds/` |
| `Audio/Fallback/` | The stand-ins the game synthesises until a recording loads; Unity does not need them | `js/audio.js` |
| `Meshes/` | FBX: `Block` (every layer, slab and piece), the island whole (`Island`) and in parts, foliage, splash crown and drop, perfect ring frame and plate, and the sea at two densities | `js/scene.js` |
| `Materials/` | One per surface, set up for the shaders below | `js/scene.js` |
| `Shaders/` | URP ports of the scene's look: `Lambert` (solids), `Foliage` (sway), `Unlit Transparent` (effects, clouds), `Water`, `Sky` (skybox) | `js/scene.js` |
| `Scripts/` | C# ports of the animation and the numbers they run on: see below | `js/*.js` |
| `Textures/` | `Cloud.png` (the cloud sprite at 4x), `Stars.png` (the star field) | `js/scene.js` |
| `Icons/UI/` | Every UI icon, white on clear at 128 px, imported as sprites to tint | `js/icons.js` |
| `Icons/App/` | The app icon at 192, 512 and 2250 px | `main-site/` |

## Units and axes

The scene's units: the tower's base is **1 unit** across, a layer is
**0.2** tall, the top of the base column is **y = 0** and the island's top
**y = -1**. The game's own numbers are a thousand times that
(`Scripts/Rules.cs`); `Scripts/World.cs` converts.

three.js is right handed and Unity left handed, so Unity's FBX importer
mirrors every mesh in x. `World.FromGame()` mirrors the game's positions the
same way, so everything lines up. Use it, not your own conversion.

## Setting up a scene

1. **Lighting > Environment**: Skybox Material `Materials/Sky`.
2. A **Directional Light** for the sun. `SceneLook` points it and sets its
   brightness.
3. `Meshes/Island.fbx` at the origin. It holds the base column, sand,
   grass, rocks and every plant, with materials already assigned. Add
   `BaseColumn` to it, with the sea's `WaterSurface` in its *Water* field,
   and call `Apply(difficulty)` when a game starts: each difficulty starts
   on a different size of base (`Rules.Difficulty.Start`).
4. `Meshes/WaterHigh.fbx` at the origin, with `WaterSurface` on it. Use
   `WaterLow.fbx` and tick *Low Quality* on `Materials/Water` for slower
   devices. `WaterHigh` has 66,049 vertices, so it needs 32-bit indices
   (Unity picks them automatically).
5. On the camera: `TowerCamera`. On empty objects: `SceneLook`,
   `CloudDrift`, `Splashes` and `GameAudio`, with their fields filled in.

Tower layers are `Meshes/Block.fbx` with `Materials/Block`, scaled to
`(sx, 0.2, sz)` and coloured per renderer with a `MaterialPropertyBlock`
holding `_BaseColor = Palette.Layer(seed, n)`.

## Scripts

| Script | Does |
| --- | --- |
| `Rules` | The slab's speed and swing, the water's rise, each difficulty's starting size. Integers, as in `js/rules.js` (the current rules version only) |
| `BaseColumn` | Sizes the island's base column to the difficulty's starting slab |
| `Fall` | A cut-off piece's tumble, bounces and splash, as in `js/fall.js` |
| `FallingPiece` | Plays a `Fall` on a block and raises its impacts |
| `World` | Game units and axes to Unity's |
| `Palette` | Layer colours, and the sky, water and island colours for each theme |
| `SceneLook` | Eases the sky after the tower's hue; applies the theme to materials, ambient light and fog |
| `WaterSurface` | Keeps the sea at the water level and feeds its shader the shore, the tower's waterline and the ripples |
| `Splashes` | The crown and drops where a piece goes in |
| `PerfectRing` | The frame and plate that spread from a perfect drop |
| `LayerGrow` | A layer's side easing back out after a run of perfects |
| `CloudDrift` | The nine clouds circling the island |
| `TowerCamera` | The follow camera, overview and free-camera offsets |
| `GameAudio` | Every sound at the game's levels and pitches, and the water loop dulling with distance |

`Rules`, `Fall` and the splash hash were checked against the JavaScript on
the same inputs and give identical results. Scoring, replays, the
leaderboard and multiplayer are not here: they are game logic and server
code, not assets.

## Things that differ from the web game

- **Lighting** is Unity's: Lambert from the main light plus a gradient
  ambient standing in for three.js's hemisphere light. Close, not
  identical.
- **Stars** are a texture laid over the screen rather than 2.2-pixel
  points, so they stretch a little on very wide or tall screens.
- **Sound** levels are all halved, because the splash plays at 1.9x, past
  Unity's volume limit of 1. Raise the mixer group to taste. The browser's
  limiter is not reproduced.
- **Random sounds** (drop, land and the fallbacks) are fixed takes of
  something the game synthesises fresh each time, so there are three of
  each to pick between.
- **Foliage in `Island.fbx`** keeps its sway in the UVs: uv0 is each
  plant's root and uv1 how far it moves. Don't let anything regenerate
  those UVs (lightmap UVs go in uv2, which is fine).
- **The checked-in `Island.fbx`** still scatters its plants clear of a
  1-unit base. Easy's base is 1.4 across, so a few plants are hidden inside
  it until `export.mjs` is run again, which scatters them clear of the
  widest base as the web game does.

## Not checked in Unity

There was no working Unity 6 install to import these into. The C# compiles
against Unity's API, the FBX files were re-imported in Blender to check
names, sizes, vertex colours and UVs, and the sounds and textures were
inspected directly. The shaders, materials and `.meta` files are untested:
if a material shows pink, select its shader again in the Inspector. If an
FBX comes in with its own materials, use *Materials > Search and Remap*: the
names match `Materials/`.
